# 一次情報 (primary_info_assets) の投入ガイド

**このパイプラインで最も重要な仕組みです。ここが枯れると記事の独自性も枯れます。**

競合のAI記事が絶対に持てないものが、産地には無限にあります。
畑の写真、実際の収穫日、糖度の実測値、その年の天候、選別の基準、生産者の言葉。
一方、上位記事を言い換えただけの記事は P-04 の `uniqueness`（25点）で10点以下になり、
`commodity_score` が上がって設計どおり reject されます。ゲートは弱めません。
代わりに、注入できる一次情報を用意します。

Googleの scaled content abuse の観点でも、ここが唯一かつ最大の分岐点です。
「AIで書いたかどうか」ではなく「そのページに独自の価値があるか」で判定されます。

---

## 何を記録するか

構えなくて大丈夫です。畑で見たこと、測った数字、お客さまに聞かれたこと。
その日のうちにメモしておくだけで十分な素材になります。

| 種別 (`asset_type`) | 何を記録するか | 例 |
|---|---|---|
| `measurement` | 測った数字 | 糖度、酸度、重量、玉数、収量 |
| `field_record` | 畑の記録 | 何月に何の作業をしたか、樹の状態、収穫の様子 |
| `weather` | その年の天候 | 雨が少なかった、暖かい日が続いた、それが実にどう出たか |
| `process` | 選別・貯蔵・出荷の手順 | どういう基準で選り分けているか、訳あり品の理由 |
| `customer_voice` | お客さまの声 | 毎年聞かれる質問、贈答での使われ方（個人が特定できない形で） |
| `public_data` | 公的統計の分析 | 農林水産省の作付面積・出荷量と、産地の実感との差 |

### 特に価値が高いもの

1. **時点のある数字。** 「甘平は甘い」ではなく「2026年1月15日に収穫した分は糖度13.2度、
   40玉を測定」。時点と測り方があるだけで、他が書けない情報になります
2. **その年ならではの話。** 「今年は雨が少なく、色づきが例年より10日遅れた」
3. **うまくいかなかった話。** 成功談より珍しく、読者にも検索エンジンにも効きます

## 書くときの約束

### `content` は公開されます

`content` は記事本文へそのまま注入され、kuri-mikan.jp に載ります。
次のものを書かないでください（公開時に法令ゲートで止まりますが、素材の時点で入れないこと）。

- **効能効果**（免疫力アップ、風邪予防、疲労回復など）。
  成分は「ビタミンCを多く含みます」まで。体にどう働くかは書けません
- **根拠のない最上級**（日本一、最高級、他産地を圧倒）
- **無農薬・減農薬・無化学肥料**（特別栽培農産物に係る表示ガイドライン）。
  栽培方法は、確認できる作業内容で書いてください
- **有機・オーガニック**（有機JAS認証がない場合）
- **お客さまの個人情報**。氏名、住所、宛先、注文内容と時期の組み合わせ。
  「◯◯市の◯◯さん」も特定につながります

### 数値には必ず根拠を書く

`numeric_claims[].basis` に、いつ・どうやって・いくつ測ったかを書きます。

```json
{
  "claim": "2026年1月収穫の甘平の平均糖度",
  "value": "13.2",
  "unit": "度",
  "basis": "自社選果場の屈折計による実測、2026-01-15、n=40",
  "verified": true
}
```

`verified: true` のものだけ投入してください。裏が取れない数値は入れません。

### 有効期限を入れる

`valid_until` は必須ではありませんが、**その年の収穫に関する情報には必ず入れてください。**
柑橘は年ごとに出来が変わります。「昨年の糖度」を今年の記事で使うと、事実と違う記述になります。

月次の棚卸し（P-18b）が期限の近い資産を拾い、`keep` / `update` / `retire` を判定します。
畑の場所、栽培の手順、選別の基準のように年をまたいで変わらない情報は `keep` のままで構いません。

## 投入手順

1. テンプレートをコピーして実データファイルを作ります（**このファイルはコミットされません**）

```bash
mkdir -p .local
cp scripts/seed/primary_assets.example.json .local/primary_assets.json
```

2. 中身を実際の記録に書き換えます

`.local/` は `.gitignore` 済みなので、`numeric_claims[].basis` に踏み込んだメモ
（測定した区画名など）を残してもリポジトリには出ません。ただし `content` は公開されるので、
そちらには書かないでください。

3. 投入します

```bash
npm run seed:assets -- --plan      # 何が入るか確認
npm run seed:assets                # 実行
npm run seed:assets -- --replace   # 既存を置き換える
```

## どう使われるか

- 記事の生成時、`applicable_clusters` が一致し、かつトピックとの関連度が高い資産が
  `usage_count` の少ない順に最大3件選ばれます
- P-01 が「どのセクションでどう使うか」を計画し（`primary_info_plan`）、
  P-02 が本文へ帰属つきで織り込みます
- 使われた資産は `usage_count` が加算されます。加算しないと同じ資産が使われ続け、
  一次情報のローテーションが機能しません
- P-04 は「一次情報が使われているか」を `eeat` と `uniqueness` で見ます

## クラスタの割り当て

1つの資産を複数クラスタに使えます（`applicable_clusters` に複数指定）。

| クラスタ | 内容 |
|---|---|
| `citrus_variety` | 品種そのもの |
| `growing` | 畑と栽培、産地 |
| `eating` | 食べ方、保存、むき方 |
| `gift` | 贈答、のし、予算 |
| `chestnut` | 栗 |
